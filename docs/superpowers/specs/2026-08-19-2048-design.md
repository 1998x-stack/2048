# 2048 — Optimization Design

Date: 2026-08-19
Repo-relative path: `docs/superpowers/specs/2026-08-19-2048-design.md`

## Goal

Optimize the 2048 variant. Priorities (user-ranked): **Performance →
Readability → Correctness → Polish.** Honest scope note: the move/merge engine
is already O(board) on a small 8×8 grid and has no measurable hot path, so this
spec does **not** invent performance work. The real, high-value work is
**readability + correctness of the tile-spawn distribution**, plus import
boilerplate cleanup.

## Current state

- `src/game_logic.py` — move/merge engine (`merge_row`, `move_left/right/up/down`,
  `add_random_tile`, `poisson_probabilities`, `get_max_value`, `is_game_over`,
  board drawing, font cache). 45 tests pass.
- Tests are standalone scripts (each with a `main()`), run headlessly with a
  pygame stub or dummy video/audio driver.

### Key defect found

`poisson_probabilities(max_value)` builds "probabilities" by sampling
`np.random.poisson(lambda_value, ...)` — i.e. **random noise normalized into
weights**. Consequences:
- The spawn distribution is **non-deterministic per call** and effectively
  untestable beyond shape.
- The randomness undermines the documented intent: "larger numbers are rarer."
- `add_random_tile` may therefore emit erratic tile values.

## Optimization plan

### B — Performance
- **No change.** The engine is already O(board) on an 8×8 grid; moves, merge,
  game-over check, and `add_random_tile` scan at most 64 cells. Any further
  micro-optimization would be unmeasurable. Recorded explicitly so reviewers
  don't invent perf work.

### A — Make the spawn distribution deterministic and testable
Replace `poisson_probabilities` (and its use in `add_random_tile`) with a
deterministic, clearly-named decreasing-weight function over the powers of two
from `2` up to `max_value`:

- For value `2^i` (i from 1 to `floor(log2(max_value))`), weight = `2**(1-i)`
  (so `2`→1, `4`→½, `8`→¼, … → strictly decreasing). Normalized to sum to 1.
- This preserves the documented intent ("larger tiles spawn less often") with a
  **stable, monotonic-decreasing, testable** distribution. Chosen over the
  classic "only 2 or 4" (option B) and over retaining today's noisy capability
  set (option C) — user approved option A.

### C — Readability
- Reduce the repetitive `sys.path` boilerplate at the top of `src/*.py`.
  Convert the in-file `sys.path.insert/append(..)` setup into a single shared
  path-init module (or a minimal package `__init__`) imported by the src files,
  keeping the headless test imports working. Targeted change, no test harness
  re-plumbing.
- Clear docstrings/names for the new distribution function.

## Architecture

- `src/game_logic.py`: replace `poisson_probabilities` with e.g.
  `_spawn_weights(max_value) -> (values: list[int], weights: list[float])`
  plus normalization; `add_random_tile` uses it unchanged in shape.
- `src/pathsetup.py` (new): holds the `sys.path` bootstrap used by `src`
  modules — removes duplicated boilerplate.
- `src/game.py`, `src/utils.py`, `src/game_logic.py`: import the path setup.

## Data flow

`add_random_tile(grid)` -> `_spawn_weights(get_max_value(grid))` ->
`random.choices(values, weights)`; pick a random empty cell; place.

## Error handling

- `get_max_value` returns at least 2, so `_spawn_weights` always has at least
  `[2]`. Normalization guards `sum(weights) == 0` → fall back to uniform.
- Full board: `add_random_tile` returns `False` unchanged.

## Testing & verification

Baseline: run `tests/test_game_logic.py test_edge_cases test_render
test_state test_event_assets test_integration` (45 pass).

New tests to add (TDD):
1. `_spawn_weights` returns powers of two `<= max`, weights positive, and

2. Weights are **strictly decreasing** in value (semantics: scaling larger is
   rarer) for a multi-element set.
3. `add_random_tile` still returns `False` on a full board (existing) and
   spawns a value `>=2` and `<= max` (existing), now with a **deterministic**
